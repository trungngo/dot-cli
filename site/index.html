Set up any machine from your dotfiles.

dot reads bundles of YAML from your repository, works out what this machine is, and links, copies, templates, installs and runs setup steps in dependency order. It shows you the plan before it changes anything.

Plan, then apply

See every change before it happens.

Every step plans without side effects first. Run dot plan to read the diff, then dot apply when it looks right.

$ dot plan

  block ~/.zshrc

Nothing changed yet. Run dot apply to continue.
Why dot

One binary. Your repo. Nothing hidden.

Built for people who keep their machines in git and want the setup to be boring.

{ }

Bundles and a graph

Each bundle is a list of steps with requires and after edges. dot resolves them into one order, runs each bundle once, and skips the dependents of a failure.

os

Profiles and facts

dot detects OS, distro, arch, role (desktop or server), WSL, containers, VMs, and the package manager. Profiles pick bundles from those facts, and when: narrows any step.

dry

Plan, status, diff

dot plan, apply --dry-run, status for drift, and diff. dot remove undoes what was recorded.

pkg

Real package managers

apt, dnf, zypper, pacman, apk, Homebrew and casks, snap, winget, scoop, and VS Code extensions, each with its own package names.

key

Secrets stay out of git

Bundles ask for secret("name"). Values come from an owner-only env file or LastPass, and they are redacted in all output and logs.

ssh

Remote machines

dot apply --host user@server installs dot on the server, syncs the repo, and hands secrets over ssh in memory only. dot cloud-init does the same on first boot.

Your repository, your rules

Plain YAML and plain files.

Nothing to learn beyond a small set of directives. Configuration is a repo you already own, not a service you have to sign in to.

  • Link, copy, template files, including managed blocks inside files you don't own.
  • Services, users, macOS defaults, PATH and env as first-class steps.
  • Inspect first: dot check, dot doctor, dot why and dot graph.
  • Reproducible installs from a release checked against SHA256SUMS.

Install

One command, then dot apply.

The installer fetches the release, checks it against SHA256SUMS, and puts dot on your PATH. Add a dotfiles repo to set the machine up in the same step.

# Install dot only
curl -fsSL https://raw.githubusercontent.com/trungngo/dot-cli/main/install.sh | sh

# Install, then clone and apply your dotfiles
curl -fsSL https://raw.githubusercontent.com/trungngo/dot-cli/main/install.sh \
  | sh -s -- https://github.com/you/dotfiles.git

# Pin a release
curl -fsSL https://raw.githubusercontent.com/trungngo/dot-cli/v0.1.0/install.sh \
  | DOT_VERSION=v0.1.0 sh
# Install dot only (Windows PowerShell 5.1 or PowerShell 7)
iwr -useb https://raw.githubusercontent.com/trungngo/dot-cli/main/install.ps1 | iex

# Install, then clone and apply your dotfiles
$env:DOT_DOTFILES_URL = 'https://github.com/you/dotfiles.git'
iwr -useb https://raw.githubusercontent.com/trungngo/dot-cli/main/install.ps1 | iex

# Pin a release
$env:DOT_VERSION = 'v0.1.0'
iwr -useb https://raw.githubusercontent.com/trungngo/dot-cli/v0.1.0/install.ps1 | iex

No token needed for dot's public releases. A GitHub token is only used for a private dotfiles repository.
